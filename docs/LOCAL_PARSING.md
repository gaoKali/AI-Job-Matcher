# 第 3 步：浏览器本地简历文字读取

日期：2026-10-04。状态：完成。只改动读取所需逻辑与反馈，保留现有 UI、三步骤、需求表单和模拟岗位。

## 当前能力

PDF.js 6.4.299 与 Mammoth.js 1.13.0 完整官方 npm 发行包已固定保存在 assets/vendor，许可证一并保留。PDF 的主库、Worker、CMaps、标准字体版本一致，不访问 CDN。测试发现旧目录的字体资产不完整，已更换官方完整发行包，中文 CID 字体复测通过。

文件通过 File.arrayBuffer 在本机读取，ArrayBuffer 仅传给浏览器 Worker。PDF 按页、视觉行顺序提取，重复宽空白分隔的稳定双栏先左后右；DOCX 使用 extractRawText 读取正文与表格。三种入口都进入唯一内存变量 `window.resumeText`，后续分析的入口只读取这个变量，当前仍故意调用 Mock，不向任何服务发送简历。

成功后显示“简历读取成功”和字符数。预览使用 textContent，默认折叠，不执行内容中的 HTML；支持收起与重传。切换输入方式、失败、重传和刷新都会清除旧数据，读取中的新文件会取消旧任务，迟到结果不会覆盖新输入。

## 自动检查与隐私边界

13 项 Node 测试通过，覆盖视觉行与双栏顺序、DOCX 结构/声明解压大小、文件校验、Mock 数据隔离、排序筛选、本地字节传递、浏览器 Worker 异常、解析错误、超时/取消、资源释放和迟到结果。异常与超时通过离线注入模拟，不假称在真实浏览器中等待了 45 秒。

没有 fetch/上传接口调用出现在页面交互及解析适配器中；PDF.js 内部仅 GET 项目内的字体等静态资产。服务器仅允许 GET/HEAD，拒绝 POST，限定静态文件白名单，不保存文件、正文或请求记录。CSP 只允许同源资源和 Worker。没有数据库、localStorage、sessionStorage、IndexedDB 或外部服务配置。

限制：文件 10MB，PDF 100 页，提取文字 150,000 字符，45 秒超时，DOCX 声明解压大小 64MB。解析在 Worker 中，取消/超时终止 Worker，避免卡住页面。

## 已知边界

扫描件和图片内文字不做 OCR。复杂混合分栏、旋转文字、图形、非标准字体可能影响顺序或完整性；用户应展开核对。DOCX 页眉页脚、文本框、图片里的文字不保证提取。部分 PDF 页面无文字时标明页号，不冒充全文完整。没有未修复的已知测试失败，但不能保证所有特殊文件均可读。

PDF 的 Worker 与模块需要本地 HTTP 地址，直接 file 协议打开会友好提示。启动网页.cmd 已改为启动本地静态预览后打开地址；无需用户操作命令。

本阶段停在真实文字读取，AI 与岗位匹配仍使用模拟数据。
