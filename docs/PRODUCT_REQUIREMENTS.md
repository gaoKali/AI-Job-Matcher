## 目标与当前阶段

面向中国大陆个人求职用户，提供公开网页：上传简历、确认提取的信息、分析优势和不足、推荐求职方向、按需求发现真实岗位、解释匹配分数与差距，并支持后续针对具体 JD 优化简历。

由开发助手负责实际编程、创建文件、运行、测试和修复。此阶段仅完成 Skill 阅读和规划，不申请 API Key、不更改服务配置、不发布网站。后续先做本地可验证版本，再确定公开运行方案。

优先降低成本、减少配置、中文易用。公开使用者无需编程或提供 API Key。区分“代码托管到 GitHub”和“网页运行环境”：本产品包含服务端解析、密钥保护与模型调用，需要支持服务端的运行环境。具体托管方案、免费额度、模型价格和搜索可用性在部署阶段核验，不预先承诺永久零成本或无限免费。

## 首版与后续范围

首版必须覆盖 PDF/DOCX 上传、文本预览与纠正、候选人结构化信息、简历分析、职业方向、需求输入、真实岗位搜索、0–100 分及理由和差距、原始申请入口。粘贴简历和已有 TXT 能力作为辅助入口。

具体 JD 的定向优化安排在后续迭代，架构与事实证据从首版预留。扫描 PDF 的 OCR、简历排版导出、多版本管理、面试训练均后置。首版不做账号、数据库、简历历史、HR 批量筛选、自动投递或招聘网站登录。

## 用户流程与页面行为

1. 用户看到简明隐私说明，选择 PDF/DOCX 或粘贴文本。文件解析阶段不向模型发送材料。
2. 显示解析结果和异常；用户可纠正错序、缺失文字及结构化字段。扫描件、加密件、损坏件不能返回伪造的成功结果。
3. 用户填写城市、目标岗位和行业，可选填经验、薪资与限制条件。不确定目标时允许先做职业方向分析。
4. 用户确认将必要简历内容发送给当前模型服务后开始分析；显示事实、推断、建议和待补充信息。
5. 用户接受或修改求职方向后搜索真实公开岗位。搜索目标以用户明确选择为准，推荐方向不能静默覆盖目标。
6. 岗位卡片展示名称、公司、城市、来源、薪资与日期（有据才展示）、文本完整度、评分依据、主要差距和原始岗位链接。
7. 搜索为空、摘要不足或 AI 失败时如实说明，允许调整条件或补充真实 JD；不生成示例岗位冒充搜索结果。
8. 后续可选择岗位或粘贴具体 JD 生成定向优化建议、前后对比及待确认事项。申请由用户在原始平台完成。

## 输入与数据契约

| 对象 | 最少字段与要求 |
| --- | --- |
| 解析结果 | 文本、格式、解析器、可获得时的页数、警告；原文件名只用于本次界面，不发送给模型 |
| 候选人资料 | 工作经历（公司、岗位、起止时间、职责、真实成果）、行业、技能及证据、教育（学校、专业、学历、时间）、项目（角色、行动、成果）、证书；每项保留原文片段和可获得的位置 |
| 用户需求 | 城市、目标岗位、行业、经验、薪资、必要限制；未填保持未知，不由模型补成用户偏好 |
| JD | 标题、公司、城市、职责、必备要求、重要要求、加分项、教育与经验门槛、发布时间、来源链接、获取时间、完整度；没有公开依据的字段为空 |
| 分析结论 | 优势、不足、方向与理由、优先改进项；各结论区分事实/推断/建议并关联证据 |
| 匹配结果 | 岗位 ID、总分或无法评估、各维度得分、证据覆盖率、匹配原因、差距、硬条件状态、规则版本；不得改写来源链接 |
| 后续优化 | 原文、建议改写、对应 JD 要求、修改理由、事实依据、待用户确认项 |

缺失信息不得默认为零年经验、无学历或无技能。工作时间重叠不得简单累加，日期不完整时标记估算依据。用户补充内容标记来源为用户确认，保留与原文件的区别。事实资料和分析结论分开，防止后续模型将建议重新读取为事实。

## 文件解析

- 首版支持文本型 PDF 和 DOCX，规划沿用当前 10MB 上限；具体上传限制还需结合运行环境验证。
- 校验扩展名、MIME、文件特征与大小；为解压、页数、提取文本长度、处理时长和并发设置资源上限。
- 先提取原文，再轻度清理格式；保留原始依据，不在解析阶段改写经历。
- 支持多栏、中文、时间、列表的典型样本验证；无法可靠恢复顺序时提示用户检查。
- 扫描 PDF 提示目前需文本型文件或粘贴文字；OCR 后续单独评估。加密、空内容、损坏与超限应有明确中文错误。

## 简历诊断与职业方向

诊断检查结构完整性、时间与描述一致性、职责与成果表达、技能证据、信息缺失及可读性，按优先级给出改进建议。“未描述”与“确定不具备”分开。

方向推荐根据已证实经验、技能、行业知识和可迁移能力，结合用户目标输出少量明确方向及理由、门槛、待补充信息。不凭姓名、性别、年龄、婚育等信息评分，不承诺录用、薪资或面试概率。初期优先给解释清楚的方向，不制造未经校准的精确职业适合度分数。

## 真实岗位搜索与链接

- 通过独立搜索适配器获得合法公开搜索结果或授权接口，支持未来替换来源；模型负责理解文本，不负责凭记忆生成实时岗位。
- 默认优先近 30 天岗位，日期无法确认标为“日期待确认”；已过期默认隐藏。日期状态不等于岗位仍在招聘或页面真实性已完全验证。
- 保留来源 URL、来源平台、获取时间和证据；来源字段由程序保护，禁止模型创建或改写。
- 原始岗位详情链接可作为申请入口；未确认有直接投递链接时明确“查看原始岗位并申请”，不伪造一键投递。
- 过滤首页、搜索列表、登录页和非岗位页面，去重；页面可能要求用户登录，应如实提示。
- 摘要和完整 JD 分开标记。没有完整职责与要求时只作初步参考，不当作完整 JD 进行确定性缺口判断。
- 不绕过登录、验证码或访问限制。网页抓取需白名单、私网拦截、重定向复检及资源限制。未来扩展企业官网时同样执行来源检查。

## 0–100 分的可解释规则

以下是待实现、待样本校准的 v0.1 评分提案，不是原 Skill 已提供或当前代码已实现的算法。

| 维度 | 初始权重 | 使用依据 |
| --- | --- | --- |
| 核心技能 | 35 | JD 必备/重要技能与候选人真实应用证据 |
| 职责和项目经验 | 30 | 工作职责、项目行动、范围及成果 |
| 行业与业务经验 | 15 | 直接经验及注明迁移依据的可迁移经验 |
| 学历和资格 | 10 | 仅使用 JD 明确要求的学历、专业和证书 |
| 用户求职条件 | 10 | 城市、工作形式、薪资等用户明确条件 |

- 对每个要求先标记“满足、部分满足、不满足、未知”，再解释引用的候选人证据和 JD 证据。维度内部必备项优先于加分项。
- 模型提取和判断条目，服务端按版本化规则计算总分，不让模型任意编一个总分。
- 首版提案：单项满足=1、部分满足=0.5、明确不满足=0；没有事实支持的项目为未知，不冒充不满足。
- 完整 JD 中完全未设要求的维度标为不适用，对适用维度重分配权重。摘要缺失造成的未提及不能标为不适用。
- 证据覆盖率为适用权重中可判断的比例。覆盖率低于 60% 时不出数值，显示“信息不足，补充简历或完整 JD 后评估”。阈值需后续校准。
- 覆盖率达标时，对未知条目计算上下界：未知贡献分别按 0 与 1 计算得到下界和上界；0–100 的展示整数取下界并明确标为“已证实匹配分”，同时展示覆盖率和可能区间。完整信息时区间收敛为同一个分数。
- 硬条件单独显示为满足/不满足/未知。未知不能判定淘汰；明确不满足必备门槛时不列入优先推荐，即使其他维度较高也解释原因。
- 相同输入与规则版本应保持评分一致；评分代表材料匹配程度，不是录用概率。方向推荐、关键词预排序与正式岗位匹配分必须区分。
- “缺少证据”“岗位硬性差距”“可通过表达改进”“需实际学习或补经历”分别说明，禁止把建议补学的技能当作已有优势。

## 后续真实 JD 优化

基于用户确认资料与具体 JD，按重要性重排已有内容，改善动词、结构和术语，使用 STAR 组织项目；只在有真实数字时量化。展示原文、改写和理由。无法读取岗位页面时让用户粘贴 JD，不猜测其内容。尚未确认的成果单独列为补充问题，不写进最终稿。支持复制文字起步，排版与导出后置。

## 模型可替换与运行边界

业务模块通过统一的结构化模型接口调用模型，避免页面或 Skill 直接绑定厂商。优先考虑 Qwen；保留 DeepSeek、其他 OpenAI-compatible API，以及独立 Agent API 适配器。

地址、模型名、密钥、超时和输出能力放在服务端配置；更换兼容服务尽量只改配置。Agent API 可有不同协议，通过适配器处理运行状态、轮询/流式结果和取消，不假设它必然兼容 Chat Completions。统一输出 Schema、事实规则和错误处理；增加新适配器不修改业务输出结构。

开发和自动检查使用明确标识的 Mock，避免消耗真实额度；Mock 不能在正式模式冒充真实 AI 或真实岗位。缺少配置时给出明确服务状态，解析与粘贴仍可工作。此轮不读取或修改已有本机密钥。

## 隐私、公开访问与成本

- 简历默认仅在本次处理内存中使用，不写数据库、持久文件、浏览器存储或普通日志；支持清空本次材料。
- 模型调用前说明发送给哪个服务及发送内容；优先移除姓名、电话、邮箱、地址等非必要信息。第三方保存策略需在上线前核验，不能声称整个链路绝不留存。
- 搜索只发送去标识后的求职条件；禁止发送完整简历、联系人信息或用户真实姓名。搜索缓存不得保存简历或候选人分析，缓存查询的保留时间需要说明。
- 密钥只保存在服务端且不提交 Git；日志不记录原文件、简历正文、完整提示词、联系方式或密钥；不暴露内部路径。
- 简历和岗位网页均视为外部不可信数据，文本中的指令不能覆盖系统规则或触发工具操作；页面安全渲染输出。
- 公开服务上线前完成请求限流、单次资源限制、模型调用预算、超时、取消与合理错误提示；重试有上限，避免重复点击造成重复请求。
- 免费额度、区域可用性和服务条款在选型时验证；免费资源不可用时显示服务状态，不静默切换付费服务或产生无法控制的费用。
